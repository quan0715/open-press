## 什麼是 OpenPress

OpenPress 是一個 **AI-first 固定版面文件框架**。創意 skill 負責決定要做什麼；OpenPress 負責 workbench、行內編輯、評論標記、渲染、PDF/圖片/Word 匯出，以及部署流程。

OpenPress 適合那些**內容持續變動、但輸出格式必須保持穩定**的文件：提案、白皮書、報告、課程講義、書籍、社群卡片，以及簡報投影片。

### 為什麼需要 OpenPress

正式文件不只是文字。提案、白皮書、教學講義、研究筆記與產品手冊通常還需要固定版面、清楚章節、可追蹤的 source、PDF 匯出、公開 reader，以及後續的長期維護。OpenPress 的定位，是把這些需求放進同一個文件 workspace。

OpenPress 不是「請 AI 幫我做一份檔案」的工具，而是一套 AI-first document framework。你可以讓 Claude Code、Cursor、Codex 或其他 agent 協助寫作與調整，同時透過固定的 source model 保持文件結構的可追蹤性。

### 與一般 AI 文件產出方式的差異

| 做法 | 適合情境 | 常見限制 | OpenPress 的差異 |
| --- | --- | --- | --- |
| AI 產 Word | 快速整理文字、內部草稿 | 版面容易漂移，版本差異難審查 | source 是文字與元件，可 diff、可重建 |
| AI 產 PDF | 一次性簡報或短文件 | 產出後很難精修與延伸 | PDF 是 build artifact，不是唯一 source |
| AI 產 HTML | 需要快速展示頁面 | print、分頁、頁碼、封面與 TOC 不穩定 | 從一開始就以固定版面文件為核心 |
| Markdown 網站 | 技術文件與長文 | 不一定有 A4/PDF 契約 | 同時支援 web reader 與 PDF 交付 |

### OpenPress 的主要優勢

| 優勢 | 對使用者的意義 |
| --- | --- |
| 真實檔案作為來源 | 資料表、圖片、截圖與 component 都在 workspace 中，AI 只整理可追蹤素材 |
| 固定 A4 版面 | 文件一開始就朝可列印、可匯出、可審查的形狀前進 |
| Source-first | 章節、版面與元件可 diff、可 review、可重建 |
| 同源輸出 | 同一份 source 產生 web reader、正式 PDF 與 Word DOCX，不需要維護多套內容 |

### 什麼時候該用 OpenPress

典型使用情境包括：

| 使用情境 | OpenPress 能幫上的地方 |
| --- | --- |
| 論文與研究筆記 | 在既有實驗資料夾中引用真實數據、圖檔與結果表，整理成可審查的章節與 PDF |
| 教學講義 | 把課綱、範例程式、練習題與答案附錄放進同一份文件 |
| 計畫書與商業提案 | 引用真實商業規則、價格表、截圖與圖表，輸出可公開閱讀的 reader 與正式 PDF |
| 簡報投影片 | 可版本化的 16:9 投影片，與其他文件共享同一個 workspace |

判斷方式很直接：如果一份文件需要保留真實資料、圖片來源、元件邏輯與修改歷程，就不該只停在一次性生成。把它做成 OpenPress 專案，AI 負責整理、補寫與調整；source 負責留下證據、版本與可重建的 reader、PDF 與 Word DOCX。
