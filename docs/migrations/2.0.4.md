# Migration: v2.0.4

## Summary

`Frame` now supports optional auto layout through `layout={{ ... }}`. Existing
Frames keep the same behavior when `layout` is omitted. Workspaces do not need
a forced rewrite, but custom slide/page layouts can migrate layout-only wrapper
elements into nested Frames for better region identity, inspectability, and
agent edits.

## Workspace source changes

### Layout-only wrappers -> nested `Frame layout`

- **Find**: `rg -n '<Frame|className=.*(grid|flex|gap-|p-|px-|py-|overflow-hidden)' press/`
- **Replace**: migrate only layout-only containers that represent meaningful
  regions. Keep visual styling in workspace components/classes.
- **Why**: nested Frames now provide stable region identity plus optional
  stack/grid layout constraints.

Before:

```tsx
<Frame frameKey="intro" role="canvas.slide" className="reader-page--intro">
  <section className="grid h-full grid-cols-[1fr_420px] gap-8 overflow-hidden p-24">
    <div className="grid gap-6">...</div>
    <aside className="grid gap-4">...</aside>
  </section>
</Frame>
```

After:

```tsx
<Frame frameKey="intro" role="canvas.slide" className="reader-page--intro">
  <Frame
    frameKey="intro-layout"
    role="canvas.region"
    layout={{
      mode: "grid",
      columns: "minmax(0, 1fr) 420px",
      gap: 32,
      padding: 96,
      width: "fill",
      height: "fill",
      clip: true,
    }}
  >
    <Frame frameKey="intro-main" role="canvas.region" layout={{ mode: "stack", gap: 24 }}>
      ...
    </Frame>
    <Frame frameKey="intro-side" role="canvas.region" layout={{ mode: "stack", gap: 16 }}>
      ...
    </Frame>
  </Frame>
</Frame>
```

### Keep root page sizing in `<Press page>`

- **Find**: `rg -n 'width:|height:|--openpress-page-width|--openpress-page-height|page=' press/`
- **Replace**: do not move page geometry into root `Frame layout.width` or
  `Frame layout.height`.
- **Why**: root page size is still owned by `<Press page="...">`. `Frame layout`
  sizing is for internal layout constraints.

### Do not migrate semantic templates into core presets

- **Find**: `rg -n 'cover|sidebar|media-left|two-column|feature-grid' press/`
- **Replace**: keep semantic layout names in workspace components or skills.
- **Why**: core has no `layout="cover"` or preset API. Use
  `mode: "stack"` / `mode: "grid"` plus constraints.

## Runtime / API changes

- `FrameProps` now accepts optional `layout`.
- `layout.mode` supports `"stack"` and `"grid"`.
- `width` / `height` support `"hug"`, `"fill"`, number, or CSS string.
- Existing `Frame` behavior is unchanged when `layout` is omitted.
- Nested `Frame` is the recommended region/container primitive.

## Manual steps

- Review visual output after migrating layout wrappers. Layout constraints can
  slightly shift spacing compared with hand-authored Tailwind wrappers.
- Prefer migrating one repeated layout pattern at a time, not the whole
  workspace.

## Migration QA

- **Checkpoint**: Workspace renders.
  - **Run**: `npm run build`
  - **Expected**: exits 0.
  - **If failing**: fix invalid `layout` props, forbidden slide object identity
    props, or layout JSX errors before continuing.

- **Checkpoint**: Frame layout hooks appear where migrated.
  - **Run**: `rg 'data-openpress-layout-mode|openpress-frame-layout' public/openpress dist-react`
  - **Expected**: migrated Frames appear in rendered output.
  - **If failing**: confirm the migrated source uses `<Frame layout={{ ... }}>`
    and rerun the build.

- **Checkpoint**: No accidental root page sizing migration.
  - **Run**: inspect migrated root Frames in `press/`.
  - **Expected**: page size remains configured through `<Press page>`, not root
    `Frame layout.width` or `Frame layout.height`.
  - **If failing**: move page geometry back to `<Press page>` or theme tokens.
