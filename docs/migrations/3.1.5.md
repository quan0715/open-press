# Migration: v3.1.5

## Summary

OpenPress 3.1.5 keeps rendered page counters and inline editing aligned with
their authored sources. Global page folios now come from the final document
frame order, while syntax-bearing inline content opens its original MDX instead
of writing rendered LaTeX or inline-code text back to source. Pending comments
now use a floating review dock, leaving the toolbar comment action as a simple
on/off control. Document search now lives in the native right panel and
normalizes case, spaces, and hyphens while navigating results cyclically.

Existing Press content does not require a general rewrite. Workspaces with a
custom `SectionsPage` footer should check whether it displays section-local
`pageIndex` values where a global document folio was intended.

## Workspace source changes

### Use `PageFolio` for global document page numbers

- **Find**:

  ```bash
  rg -n 'pageIndex\s*\+\s*1|totalPages' press --glob '**/*.tsx'
  ```

- **Replace**: when the footer is meant to match the reader or Workbench page
  counter, import `PageFolio` from `@open-press/core` and render it in the page
  footer:

  ```tsx
  import { Frame, MdxArea, PageFolio, Press } from "@open-press/core";

  <footer className="page-footer">
    <span>{sectionTitle}</span>
    <PageFolio variant="slash" separator=" / " />
  </footer>
  ```

- **Why**: `SectionsPageProps.pageIndex` and `totalPages` describe the current
  section overflow chain. They restart for each section and therefore cannot
  represent the final page position of the whole document. `PageFolio` is
  resolved after pagination against the final frame order, which is the same
  global order used by the reader and Workbench counters.

Keep `pageIndex` and `totalPages` when the design intentionally displays a
section-local counter. Label that counter as a section or chapter page so users
do not mistake it for the document folio.

## Runtime / API changes

### Source-aware inline editing

Syntax-free rendered text remains directly editable. Blocks containing LaTeX,
inline code, Markdown emphasis, links, nested rendered elements, MDX
components, or formatted table cells open their original MDX source instead.

Source edits now replace the exact mapped source range and preserve surrounding
text and indentation. No MDX rewrite is required. Do not pre-convert `$...$`,
backticks, or other authored syntax into rendered HTML.

### Page-number source contract

`SectionsPageProps.pageIndex` and `totalPages` remain section-local; their API
semantics have not changed. Use `PageFolio` whenever a component needs the
global page number or global total after final pagination.

### Comment review interaction

The toolbar comment action now only enables or disables comment inspection. It
no longer opens a separate pending-comments menu. When comment inspection is
enabled, pending comments appear in a bottom-centered floating review dock with
cyclic previous/next navigation, position, clear-current actions, and the
comment editor. Selecting rendered content creates a new comment in the same
dock; selecting a pending comment loads its original note for editing.

The previous rendered-page marker rail, selection outline, and inline composer
have been removed. Comment navigation now shows one compact proposal-style
location marker beside the active source target. It identifies position without
framing or recoloring the document content.

Comment source paths returned with a workspace `press/` prefix now resolve to
the same inline source blocks as workspace-relative paths. No source or settings
migration is required.

### Document search interaction

Search is now a first-class right panel rather than an overlay. Results are
computed from the in-memory search index as you type, wrap instead of scrolling
horizontally, group matching snippets by source location, and cycle through
matches with the previous/next controls. Queries treat `OpenPress`,
`open-press`, and `open press` as equivalent.

No source or settings migration is required. Custom Workbench integrations that
relied on search appearing as an overlay should treat the right panel as the
stable interaction surface instead.

## Manual steps

- Review custom `SectionsPage` footers found by the search above and decide
  whether each counter is global or intentionally section-local.
- Review one syntax-bearing block in the local Workbench without saving over
  the source until its original MDX delimiters are visible.
- Do not deploy as part of migration.

Mixed Chinese and Latin typography is not automatically migrated in this
patch. If a custom Press shows unusually large Chinese character gaps, inspect
its authored theme for `text-justify`, `text-align: justify`, and Latin-only
body font stacks. Treat any typography change as a Press design decision and
review pagination before accepting it.

## Migration QA

- **Checkpoint**: Global document counters use the global folio source.
  - **Inspect**: open `/workspace`, navigate to a page in a later section, and
    compare the left-panel counter with the visible document footer.
  - **Expected**: a footer intended as a document folio matches the left-panel
    current page and total.
  - **If failing**: confirm the footer uses `PageFolio`, not
    `pageIndex + 1` or section-local `totalPages`.

- **Checkpoint**: Authored MDX syntax survives inline editing.
  - **Inspect**: click a syntax-free paragraph, then a paragraph containing
    `$...$` or backticks.
  - **Expected**: plain text edits directly; syntax-bearing content opens the
    source editor with its original delimiters intact. Saving changes only the
    selected source range.
  - **If failing**: stop and report the affected block and source path. Do not
    save rendered text over the MDX source.

- **Checkpoint**: Comment review stays separate from the toolbar toggle.
  - **Inspect**: open a Press with at least one pending comment and enable the
    comment tool from the Workbench toolbar.
  - **Expected**: the toolbar control stays icon-sized, the floating review dock
    appears, and previous/next cycles through pending comments without opening a
    toolbar menu. Editing happens in the dock, while the selected source block
    scrolls into view with one compact location marker beside it, but without a
    selection outline or inline composer.
  - **If failing**: report the comment source path and whether the dock or inline
  marker failed to resolve. Do not clear the comment as a workaround.

- **Checkpoint**: Search stays in the right panel and moves through results.
  - **Inspect**: open document search, enter `openpress`, then use the previous
    and next controls past the first and last result.
  - **Expected**: results appear immediately in the right panel, text wraps
    without horizontal scrolling, and navigation cycles across all normalized
    matches.
  - **If failing**: report the query, visible result count, and selected source
    location. Do not switch to an overlay as a workaround.

- **Checkpoint**: Every Press renders.
  - **Run**: `npm run build`
  - **Expected**: validation and rendering succeed for every Press.
  - **If failing**: resolve the matched custom footer, source-edit, or normal
    build error before continuing.

- **Checkpoint**: Pagination remains visually stable.
  - **Inspect**: review affected Presses in `/workspace`, including mixed
    Chinese/Latin prose and pages whose footer changed.
  - **Expected**: folios match, and there is no new overflow, clipping, or
    unexpected page-count change.
  - **If failing**: fix the authored Press theme or footer layout and rebuild
    before completing migration.
