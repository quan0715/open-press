# OpenPress 3.1.1 migration

## Who needs this

Existing workspaces that still store `page`, `captionNumbering`, `pdf`, or
`deploy` settings in `package.json#openpress`.

## Runtime / API changes

- The authored settings source is now `openpress/settings.json` with
  `"version": 1`.
- Workspace Appearance (`colorMode` and `accent`) is stored in that file, so
  it is consistent across browsers that open the same workspace.
- The old `package.json#openpress` object remains readable for compatibility,
  but `open-press doctor` reports it as a pending migration.

## Migration

Preview and apply the safe migration:

```bash
open-press doctor . --json
open-press upgrade . --dry-run
open-press upgrade .
```

The upgrade command writes normalized settings first and removes the legacy
package field only after the write succeeds. It stops without changing either
source when it finds an unsupported legacy field or a conflicting value in an
existing `openpress/settings.json`.

## Find

```bash
rg -n '"openpress"|"pdf"|"deploy"|"captionNumbering"' package.json openpress/settings.json
```

## Migration QA

1. Run `open-press doctor . --json`.
   Expected: `settingsMigrationRequired` is `false` and `settingsSource` is
   `"settings"`.
2. Confirm `package.json` no longer contains a top-level `"openpress"` field.
3. Run `npm run build`.
   Expected: render succeeds and `public/openpress/settings.json` contains only
   `version` and `appearance`.
4. Open `/workspace/settings`, change Appearance, reload, and confirm the
   selection remains active.
