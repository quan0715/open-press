# Migration: v3.1.1

## Summary

OpenPress moves authored workspace settings into
`openpress/settings.json` and aligns skill installation with the current v1
lockfile plus canonical-link model. Existing Press content does not require a
rewrite.

## Workspace source changes

### `package.json#openpress` -> `openpress/settings.json`

- **Find**:
  `rg -n '"openpress"|"pdf"|"deploy"|"captionNumbering"' package.json openpress/settings.json`
- **Replace**: preview and apply the safe migration with
  `open-press upgrade . --dry-run`, then `open-press upgrade .`.
- **Why**: the authored settings source is now `openpress/settings.json` with
  `"version": 1`. Workspace Appearance (`colorMode` and `accent`) is stored
  there, so browsers opening the same workspace share the selected theme.

The old `package.json#openpress` object remains readable for compatibility.
Upgrade writes normalized settings first and removes the legacy package field
only after the write succeeds. It stops without changing either source when it
finds an unsupported legacy field or a conflicting value in an existing
settings file.

## SKILL catalog changes

- Run `npm run openpress:skills` once after upgrading. OpenPress uses
  `.agents/skills/` as the canonical project install and maintains
  `.claude/skills/` links for Claude Code.
- New workspaces install seven explicit workflow skills. Repository membership
  no longer means a skill is installed by default.
- `openpress-explanatory-visuals` replaces `openpress-diagram-drawing` as an
  optional explanatory SVG and approval-gated Image Gen workflow. Install it
  with `open-press skills add explanatory-visuals .`.
- OpenPress no longer distributes or manages `chinese-ai-writing-polish`.
- Sync removes OpenPress-owned `chinese-ai-writing-polish` and
  `openpress-diagram-drawing` entries from `skills-lock.json`, but leaves their
  local `.agents/skills/` and `.claude/skills/` content untouched.
- Untracked project-owned skills under `.agents/skills/` are preserved.

## CLI changes

- `doctor` reports pending workspace-settings migration and validates current
  local skill directories plus agent links even when its registry lookup is
  cached.
- `skills:sync` reads the v1 `skills-lock.json` `skills` map, refreshes exact
  tracked optional and third-party skills, installs the seven default workflow
  skills, retires obsolete OpenPress lock entries, and repairs configured agent
  links.
- `skills add explanatory-visuals` installs and verifies the optional official
  visual workflow without changing the default bundle.
- Malformed or unsupported lock schemas, failed upstream commands, and
  incomplete post-sync installs now return a non-zero exit code.
- `upgrade` refreshes skills even when the framework package is already current,
  unless `--no-skills` is supplied.

## Runtime / API changes

- Workspace settings are authored in `openpress/settings.json`; the legacy
  package field remains readable during migration.
- Public rendered settings expose only `version` and `appearance`.

## Manual steps

- If the retired local skill copies are no longer wanted, remove
  `.agents/skills/chinese-ai-writing-polish/`,
  `.agents/skills/openpress-diagram-drawing/`, and their matching
  `.claude/skills/` entries after reviewing them for local modifications.
- Install `openpress-explanatory-visuals` only in workspaces that need
  explanatory SVG or Image Gen assistance.

## Migration QA

- **Checkpoint**: Workspace settings use the current source.
  - **Run**: `open-press doctor . --json`
  - **Expected**: `settingsMigrationRequired` is `false` and `settingsSource`
    is `"settings"`.
  - **If failing**: run the dry-run, resolve any reported conflicting value,
    then apply `open-press upgrade .`.

- **Checkpoint**: Legacy settings are removed.
  - **Run**: inspect `package.json`.
  - **Expected**: it has no top-level `"openpress"` field.
  - **If failing**: do not remove the field manually until the upgrade conflict
    has been resolved.

- **Checkpoint**: Skill lock and links are healthy.
  - **Run**:
    `node node_modules/@open-press/core/engine/cli.mjs doctor . --json --no-cache`
  - **Expected**: `skillsLockIssue` is `null`, and `skillsMissing` plus
    `skillsLinkIssues` are empty arrays.
  - **If failing**: run `npm run openpress:skills`, then rerun the checkpoint.

- **Checkpoint**: Optional explanatory visuals are opt-in.
  - **Run**: inspect `skills-lock.json` before and after
    `open-press skills add explanatory-visuals .`.
  - **Expected**: the skill is absent before explicit installation and tracked
    as `openpress-explanatory-visuals` afterward.
  - **If failing**: confirm the workspace uses the 3.1.1 CLI and rerun the add
    command without modifying the lock manually.

- **Checkpoint**: Workspace renders.
  - **Run**: `npm run build`
  - **Expected**: render succeeds and
    `public/openpress/settings.json` contains only `version` and `appearance`.
  - **If failing**: resolve settings validation or normal build errors before
    continuing.

- **Checkpoint**: Appearance persists across browsers.
  - **Run**: open `/workspace/settings`, change Appearance, and reload.
  - **Expected**: the selection remains active and another browser opening the
    same workspace reads the same selection.
  - **If failing**: confirm the workspace can write
    `openpress/settings.json` and is not serving a read-only static build.
